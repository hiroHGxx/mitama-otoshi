# 御霊おとし 開発記録

企画からゲーム公開・告知・大型アップデートまで、**2026-08-18 の1日**で完了。
特筆事項: **全工程を外出先からのリモートコントロール（スマホでAIに指示するだけ）で実施**。開発者は一度もPCの前に座っていない。

## 1. 開発体制・フロー

- 開発: Claude Code（リモートコントロール経由）。人間はスマホから日本語で指示・実機テスト・意思決定のみ
- イテレーション: 修正 → ビルド → **Claude Artifact でプレビュー**（数秒反映・本番非干渉・スマホでそのまま実機テスト）→ OK なら push → GitHub Pages 本番反映（1〜2分）
- 検証: ヘッドレス Chrome でスクリーンショット/自動プレイ（`#autotest`）/DOM検査。人間の実機確認と併用
- 例外的に人間の手を借りた操作: GitHub リポジトリの public 化と Pages 有効化（自動実行の権限チェックでブロックされたため、スマホのブラウザから2タップで実施）

## 2. 公式素材パイプライン

『月蝕綺譚』は二次創作向けに素材蔵（749点・機械可読台帳 `https://kura.vibe.co.jp/index.json`）を公開しており、これを全面活用した。

- **顔アイコン**: 正典ちびシート → `sips` で切り出し。シートはキャラごとにサイズ・レイアウト・背景色が異なる罠あり（緑背景キャラは除外して差し替え）。顔中心の校正は目視で限界があり、**codex CLI（`codex exec -i 画像...`）に目の座標をJSONで測定させ、座標補正 → 再測定のループ**で全キャラを (50%, 48%) に統一。最終的に「バストアップより上段立ち絵の頭部の方が余白があり校正しやすい」と判明し全キャラ統一
- **札絵（fuda）**: ランク8の一枚絵をタイトル背景・結果画面に使用
- **必殺カットイン（cutin）**: 公式のアニメーションwebpをそのまま演出に使用
- **楽曲**: メインテーマを afconvert で AAC 80kbps に圧縮して BGM に
- 素材蔵のお約束: 「二次創作のゲーム・画像作品に組み込んでOK（無料でも有料でも）」「素材そのままの再配布・単体販売はNG」→ **シート原本はリポジトリに含めず、ビルド時に公式からダウンロード**する構成で対応

## 3. AI画像生成（Lovart API）

公式ガイドラインが「AIによるイラスト生成OK」「正典シートのAI読み込みOK」と明記しているため、公式素材に無い絵は Lovart（GPT Image 2）で生成した。

- 導入: 公式スキル `lovartai/lovart-skill` をコード精査（stdlib のみ・通信先は lgw.lovart.ai のみ）の上グローバル導入。キーは `~/.secrets/lovart.env`（600）
- 生成実績（4枚・すべて一発採用）:
  1. 血月の夜景（皆既月蝕演出・初版）
  2. **咲耶が血月を見上げる後ろ姿**（正典シートを `--attachments` で渡してキャラ再現。演出の「のっぺり感」を構図で解決）
  3. 盤面背景（「中央〜下部はディテールなし・低コントラスト」とゲーム用途の制約をプロンプトで指定）
  4. キービジュアル（OGP/告知用。「左1/3は文字用に暗く」「壺に光球が落ちる＝ゲーム性の絵解き」を指定）
- プロンプトのコツ: 「1枚だけ・レイアウト展開不要」を明記／用途と文字スペースまで指定すると合成前提の絵が一発で出る／`--prefer-models '{"IMAGE":["generate_image_gpt_image_2"]}'`

## 4. 発信

- X で告知（初回リリース時）。構成: 本文＝内容紹介＋画像添付、**リンクはリプ欄**（外部リンク付き本文はリーチが下がるため）。「二次創作大歓迎・素材公式配布」の文脈も本文に入れ、#月蝕綺譚 タグ（公式がチェックしているタグ）
- OGP: `og:image` / `twitter:card=summary_large_image` 設定。カード画像は HTML+ヘッドレスChrome の2x書き出し（デザインツール不要）。更新時は `?v=N` でキャッシュバスト
- 告知画像: 生成キービジュアル＋公式ちび御霊＋タイトルの合成（1200×675）

## 5. ハマった制約と対策（再利用価値の高い順）

1. **GitHub Pages のキャッシュずれ**: HTML と JS を別ファイルにすると max-age 600 の境目で「新HTML＋旧JS」が配信され、ボタンが無反応になる事故が発生。→ **本番は単一ファイル**（JS全インライン）にして構造的に根絶。重いアセット（BGM・絵）だけ遅延読み込み
2. **iOS Safari のズーム**: viewport の `user-scalable=no` は**無視される**。連打がダブルタップズーム扱いされ画面が拡大。→ touchend の2連打を JS で preventDefault（ボタン除外）＋ `gesturestart` 抑止
3. **スマホスピーカーの低音**: 200Hz 未満の純音（サイン波の太鼓・鐘）は**物理的に鳴らない**。→ 倍音の豊かな Karplus-Strong 弦合成に全面移行（琴は低音でも聞こえる）
4. **Claude Artifact の制約**: 外部ホストへのリクエスト不可 → アセットは data URI 埋め込みの専用ビルドを別生成（同一ソースから2種ビルド）
5. **ヘッドレス Chrome の最小幅**: `--window-size` は幅 500px 未満に縮まらないため、スマホ幅の検証はできない。レイアウトは実機（Artifactプレビュー）で確認する
6. **物理エンジンの sleeping**: Matter.js の sleeping 有効時、壁に触れた玉が空中で眠り「刺さる」。落ち物では無効化が正解
7. **権限のガードレール**: リポジトリの public 化などの対外的操作は自動実行がブロックされる場合がある。ユーザーのスマホ操作（2タップ）に切り替えるのが最速だった

## 6. 他のゲーム・プロジェクトに活かせる知見

- **「素材配布つき二次創作歓迎」IP はゲームジャムの最高の題材**。台帳（index.json）があれば素材調達も自動化できる
- **演出の3点集中**: ミニゲームはタイトル・見せ場・リザルトの3画面だけ飾れば体感品質が跳ね上がる。盤面は視認性優先で触らない
- **AI視覚での座標校正ループ**（測定→補正→再測定）は、スプライト切り出しなど「人間の目視だと数pxの議論が空転する」作業に有効
- **演出中のゲーム停止**（pause + 遅延消滅）は、物理ゲームに「見せる演出」を後付けする際の基本形
- **カットインの再生リセット**はアニメwebpの img 要素を cloneNode で作り直すのが確実
- **実機で聞こえる音設計**: モバイルは「倍音で聞かせる」。合成音は KS 弦・帯域ノイズ打楽器が鉄板
- **配信は単一ファイル＋遅延アセット**が、更新頻度の高い個人開発ゲームのウェブ配信で最も事故らない
