# 御霊おとし 開発記録

企画からゲーム公開・告知・大型アップデートまで、**2026-08-18 の1日**で完了。
特筆事項: **全工程を外出先からのリモートコントロール（スマホでAIに指示するだけ）で実施**。開発者は一度もPCの前に座っていない。

## 1. 開発体制・フロー

- 開発: Claude Code（リモートコントロール経由）。人間はスマホから日本語で指示・実機テスト・意思決定のみ
- イテレーション: 修正 → ビルド → **Claude Artifact でプレビュー**（数秒反映・本番非干渉・スマホでそのまま実機テスト）→ OK なら push → GitHub Pages 本番反映（1〜2分）
- 検証: ヘッドレス Chrome でスクリーンショット/自動プレイ（`#autotest`）/DOM検査。人間の実機確認と併用
- 例外的に人間の手を借りた操作: GitHub リポジトリの public 化と Pages 有効化（自動実行の権限チェックでブロックされたため、スマホのブラウザから2タップで実施）

## 2. 公式素材パイプライン

『月蝕綺譚』は二次創作向けに素材蔵（749点・機械可読台帳 `https://kura.vibe.co.jp/index.json`）を公開しており、これを全面活用した。

- **顔アイコン**: 正典ちびシート → `sips` で切り出し。シートはキャラごとにサイズ・レイアウト・背景色が異なる罠あり（緑背景キャラは除外して差し替え）。顔中心の校正は目視で限界があり、**codex CLI（`codex exec -i 画像...`）に目の座標をJSONで測定させ、座標補正 → 再測定のループ**で全キャラを (50%, 48%) に統一。最終的に「バストアップより上段立ち絵の頭部の方が余白があり校正しやすい」と判明し全キャラ統一
- **札絵（fuda）**: ランク8の一枚絵をタイトル背景・結果画面に使用
- **必殺カットイン（cutin）**: 公式のアニメーションwebpをそのまま演出に使用
- **楽曲**: メインテーマを afconvert で AAC 80kbps に圧縮して BGM に
- 素材蔵のお約束: 「二次創作のゲーム・画像作品に組み込んでOK（無料でも有料でも）」「素材そのままの再配布・単体販売はNG」→ **シート原本はリポジトリに含めず、ビルド時に公式からダウンロード**する構成で対応

## 5. ハマった制約と対策（再利用価値の高い順）

1. **GitHub Pages のキャッシュずれ**: HTML と JS を別ファイルにすると max-age 600 の境目で「新HTML＋旧JS」が配信され、ボタンが無反応になる事故が発生。→ **本番は単一ファイル**（JS全インライン）にして構造的に根絶。重いアセット（BGM・絵）だけ遅延読み込み
2. **iOS Safari のズーム**: viewport の `user-scalable=no` は**無視される**。連打がダブルタップズーム扱いされ画面が拡大。→ touchend の2連打を JS で preventDefault（ボタン除外）＋ `gesturestart` 抑止
3. **スマホスピーカーの低音**: 200Hz 未満の純音（サイン波の太鼓・鐘）は**物理的に鳴らない**。→ 倍音の豊かな Karplus-Strong 弦合成に全面移行（琴は低音でも聞こえる）
4. **Claude Artifact の制約**: 外部ホストへのリクエスト不可 → アセットは data URI 埋め込みの専用ビルドを別生成（同一ソースから2種ビルド）
5. **ヘッドレス Chrome の最小幅**: `--window-size` は幅 500px 未満に縮まらないため、スマホ幅の検証はできない。レイアウトは実機（Artifactプレビュー）で確認する
6. **物理エンジンの sleeping**: Matter.js の sleeping 有効時、壁に触れた玉が空中で眠り「刺さる」。落ち物では無効化が正解
7. **権限のガードレール**: リポジトリの public 化などの対外的操作は自動実行がブロックされる場合がある。ユーザーのスマホ操作（2タップ）に切り替えるのが最速だった

## 6. 他のゲーム・プロジェクトに活かせる知見

- **「素材配布つき二次創作歓迎」IP はゲームジャムの最高の題材**。台帳（index.json）があれば素材調達も自動化できる
- **演出の3点集中**: ミニゲームはタイトル・見せ場・リザルトの3画面だけ飾れば体感品質が跳ね上がる。盤面は視認性優先で触らない
- **AI視覚での座標校正ループ**（測定→補正→再測定）は、スプライト切り出しなど「人間の目視だと数pxの議論が空転する」作業に有効
- **演出中のゲーム停止**（pause + 遅延消滅）は、物理ゲームに「見せる演出」を後付けする際の基本形
- **カットインの再生リセット**はアニメwebpの img 要素を cloneNode で作り直すのが確実
- **実機で聞こえる音設計**: モバイルは「倍音で聞かせる」。合成音は KS 弦・帯域ノイズ打楽器が鉄板
- **配信は単一ファイル＋遅延アセット**が、更新頻度の高い個人開発ゲームのウェブ配信で最も事故らない

- 検証は Artifact 相当の CSP（`connect-src 'none'`）を被せた artifact.html で `decodeAudioData` を覗く方式。
  **修正前のコードに戻した版も同じ検証にかけて 0/2 になることまで確かめた**（握りつぶす作りは、テストが素通りしても気づけないため）

## 9. 【2026-08-28】目付（UT run g1a7）で出た5件を直す — `src/game.js`

初回のユーザーテスト（受入NG2件を含む5件）の実装側の修正。意匠（`src/page.html` のCSS）は意匠担当が同時に入れた。

### 夜が明けても盤面が止まっていなかった（R-1・受入NG）

- **症状**: 結果画面でヘッダー SCORE 622／結果カード 612／BEST 612 が同時に出る。3回中2回で再現
- **原因**: 終端が定義されていなかった。`loop()` の物理更新条件が `pausedUntil` と `dexOpen` でしか止まらず、
  `tryMerge()` にも `gameOver` の判定が無いため、**夜明け後も合体が成立して `score` が増え続ける**。
  一方 `endGame()` はその瞬間の `score` で結果カードと `mitama_best` を凍結する。
  ヘッダーは `tickScore()` が `score` を追いかけるので、凍った結果カードを追い越す
- **直し方**: ①`tryMerge()` 冒頭に `if (gameOver) return;` ②`loop()` の物理更新条件に `&& !gameOver`
  ③`endGame()` の冒頭で保留中の `pendingPurges` / `pendingEclipses` を清算してから記録を確定
- **③は現状では通らない道**（保険）。演出の停止時間（カットイン1750ms・皆既月蝕2400ms）のほうが
  保留の期限（浄化900ms・蝕1500ms）より長く、`checkGameOver()` は停止中に呼ばれないため、
  `endGame()` に来た時点で両配列は必ず空になっている。**演出の停止時間を縮めたら効き始める**。
  あわせて「もう一夜」で前の夜の保留が新しい夜に加点する筋も塞がる（`restart()` は両配列を空にしない）
- **確かめ方**: `src/` を直に配るローカルサーバーで `#autotest` を回し、結果画面が出てから7秒間
  `#score` / `#final-score` / `#best` / `localStorage` の4つを0.5秒ごとに突き合わせる。
  **修正前に同じ網で1/3が赤になることを先に見てから**、修正後4/4緑を信じた

### 演出確認モード `#test` が皆既月蝕まで届かなかった（R-5・受入NG）

- **症状**: 満月成就（カットイン）は出るが、132秒待っても皆既月蝕が出ない。SCORE 55（満月1体ぶん）で止まる
- **原因**: `pair()` が咲耶を壺の左右端（`CUP_L+102` / `CUP_R-102`）へ落とすだけで、**2体が接触する保証が無い**。
  1組目は偶然合体したが、2組目は先にできた満月（r=106）に阻まれて離れたまま静止した
- **直し方**: 内向きの初速を与えて必ず寄せる（`spawnBody(8, CUP_L+94, 280, 6, 0)` と `CUP_R-94, 280, -6, 0`）。
  y=280 は**床に着いた満月の上端 y=479 に重ならない高さ**（咲耶 r=90 の下端が 370）。
  なお壺の内寸388pxは満月2体（212px）より広く**両方を床に並べては置けない**ので、満月が2体できれば接触は必至
- **確かめ方**: `#test` を3回。満月成就 約0.95秒 → 皆既月蝕 約8.85秒、SCORE 210（55+55+100）で3回とも一致

### 御霊図鑑への入口が16pxのアイコン一つだった（R-2）

- **原因**: 階梯の `<img>` に `addEventListener` を付けただけ。実測 16〜30px で半分が押し所の床（両辺24px）を割り、
  hover も focus も無く、キーボードでも届かない
- **直し方**: アイコンを `<button class="ladder-btn" type="button" aria-label="◯◯の図鑑を開く">` で包む。
  **アイコン自身の `style.width/height` は段位ごとに変わる意匠なので触らず、押し所は button 側で確保する**（CSSは意匠担当）
- **確かめ方**: 10個とも `<button>`、最小辺24px、`aria-label` 10件、`focus()` が通り、押して図鑑が開く

### 階梯に現在地の印が無かった（R-4）

- **直し方**: 生成時にボタンを `ladderBtns` に貯め、`updateHud()` から `updateLadder()` を呼んで
  `i <= maxTier` に `reached`・`i === maxTier` に `current` を付け替える
- **置き場所の勘所**: `updateHud()` は階梯の生成（ファイル後方）より**先に一度呼ばれる**ので、
  `ladderBtns` をブロック内で `const` 宣言すると ReferenceError になる。HUDの節（`updateHud` の直前）で宣言する
- **確かめ方**: 初期は index0 が reached+current、満月まで行くと current が index9 へ移り、「もう一夜」で index0 に戻る

### 開いてから2.87秒、押せるものが画面に無かった（R-3）

- **原因**: 案内カードは札絵の読み込み完了から2.6秒後（保険5秒）。その間、題字も遊び方も入口も画面に無い
- **直し方**: `setTimeout(() => ov.classList.add("peek"), 300)` を足し、案内カードを薄く先出しする（`showCard` は据え置き）。
  `#title-overlay.ready .card` は `.peek .card` より後ろに書かれているので、本番表示が上書きで勝つ
- **確かめ方**: 開いて500ms の時点で `peek` が付き、カードの `pointer-events: auto`、
  `elementFromPoint` が `#start` を返し、実際に押して盤面に入れる

  行の高さが「文字の行送り（strut）」との大きいほうで決まり、マージンが効きにくい
- 実測: 釦 **180.4×24px**（`elementFromPoint` が `.rank-open` を返す）・
  カード高は **571.4 / 623.4px** ＝ 第10便の 572.4 / 624.4px から **1px 縮んだ**

### 開いてから取りにいかない

**総数と上位の顔ぶれは同じ1回の `getTopScores` で取る。**第10便は「◯人中」のために
`getTopScores(board, 1)` を呼んでいたので、**limit を 10 に変えるだけ**で番付の中身も一緒に届く。

- 押してから取りにいかない＝**開くのを待たせない・押してから失敗する経路が生えない**
- 顔ぶれが取れなかった夜は、行を `<button>` ではなく `<span>` で組む＝**入口ごと存在しない**。
  「まだ誰もいない」も「取得できませんでした」も出さない（warn は1行残す）
- 中身は順位が確定した瞬間の控え。開くときに取り直さないので、**時間が経つと古くなる**（承知の上）
- 名前は他人が入れた文字列なので **`textContent` だけで置き、20字で切る**。
  `rank`/`score` が数でない項目は静かに捨て、1件も残らなければ `null` ＝入口を出さない

### 1人でも10人でも成立させる

- **札の高さを決め打ちしない。**行数ぶんだけ伸びるので、1人なら 340×141px の小さな板、
  10人＋自分なら 340×577px の一覧になる。空きが出ないので「スカスカ」が起きない
- 見出し「番付」＋「全国 ◯人」の2行が下支えになり、1行でも板として成立する
- 自分の行は**金泥の縁＋金泥の地**（`rgba(217,169,76,.12)`）。上位10人の中に居ればその行に印を付け、
  居なければ ⋮ を挟んで下に1行足す（**二重に出さない**）
- **自分の行だけ順位の数字も `--moon` にする。**温まった地の明るいところで `--ink-dim` は
  コントラスト比 **4.37**＝読みの床4.5を割る（実測）。他の行の地では 4.81〜5.93 で足りている
- `#bz-list` に `max-height:58vh; overflow-y:auto; touch-action:pan-y` の安全弁。
  **`body` の `touch-action:none` を打ち消さないと指で送れない**（375×667＋自分が圏外のときだけ効く）

### 確かめた4経路（すべて `pageerror` 0件）

1. **ローカル配信・素のSDK** — `standalone` なので順位は出ず、「最高記録を更新」だけ。入口も無い
2. **`sdk.js` を落とす** — 順位の枠ごと出ない。warn 1行。再開できる
3. **`dist/artifact.html` を素のまま `file://`** — sdk.js は読めて `standalone`。1と同じ
4. **`dist/artifact.html` に Artifact 相当のCSPを被せた写しを `file://`** — CSPが sdk.js を止める。
   `console.error` はCSPの拒否1件だけ

タウン内の応答は stub で模した（`submitScore` → `{ok,best,rank,improved}`、
`getTopScores` → 本番の公開API `waiwai.town/mcp` の `get_top_scores` が返した実物
`{"entries":[{"rank":1,"name":"ヒロ","score":1069}],"total":1}` をそのまま使用）。
壊れた応答（`entries` が配列でない）と無応答（自前タイムアウト2500ms）も別に流し、
**どちらも入口が生えない**ことと warn が出ることを見た。
