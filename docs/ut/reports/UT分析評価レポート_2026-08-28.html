B. エグゼクティブサマリー

遊びの芯は最後まで通った。初見の状態から、開く→入る→狙って落とす→合体させる→図鑑を見る→夜が明ける→もう一度、までが一度も詰まらずに完走した。 コントラストの破れは3画面・3幅すべてで0件、Artifact配布版でも琴の実サンプルが正しく復号された（2026-08-27に移植したCSP対策が効いている）。称号・図鑑の解禁・「これまでの誉れ」も仕様どおり動いた。

見つかった穴は5つで、性質が二つに分かれる。ひとつは記録の正しさの穴——夜が明けたあとも盤面が動き続け、ヘッダーの得点が結果カードと最高記録を追い越す（3回中2回で再現）。 もうひとつは作り込みが届いていない穴——御霊図鑑・称号・皆既月蝕という、この作品でいちばん手が掛かっている部分への入口が、16pxのアイコン1つ・自力では到達困難な段位・2.87秒の空白の向こう側にある。

最優先は R-1（夜明け後もスコアが動く）。理由は、効きと軽さの比がいちばん良いからではなく、 これが「記録が正しいこと」を前提に積み上がっている仕組み（最高得点・称号・これまでの誉れ）の土台を崩しているから。直し自体は数行で足りる。

D. 根本課題

R-1 夜が明けても、盤面は止まっていない 確信度 high

因果連鎖: loop() の Engine.update と合体処理に gameOver のガードが無い → 「夜が明けた」の裏で物理と合体が続き score が増える → だが endGame() は結果カードの得点と mitama_best をその瞬間に凍結している → 同じ画面に、追い越したヘッダーの得点と、止まった結果カードの得点と、止まった最高記録が同時に出る。

根拠: OBS-C8。C-8a-gameover.png にヘッダー622／結果カード612／BEST612 が同時に写っている。追試2回のうち1回で再現（894→901→916 に対し結果カード・BEST・localStorage は901のまま）。3回中2回。実装は game.js:638-651（endGame）と game.js:1338-1341（loop の Engine.update / checkGameOver の呼び出しが pausedUntil と dexOpen でしか止まらない）。tryMerge（game.js:466-478）にも gameOver の判定が無い。

Nielsen: #1 システム状態の可視性 ／ #4 一貫性と標準 ／ #5 エラーの予防。UX層: 構造（操作フローの終端が定義されていない）。インパクト: 効果（記録が正しくない）＋満足・信頼（同じ画面の数字が食い違う）。

別解釈・反証: 「プレイヤーは結果カードしか見ないので実害がない」という読みは成り立つ。ただしヘッダーはオーバーレイの外にあり、結果カードと同時に見える位置にある（証拠画像で確認）。また、あふれた瞬間に成立した合体の点が最高記録に入らないのは、プレイヤーから見れば「損をした」側の食い違いである。

R-2 いちばん作り込んだ場所への入口が、16pxのアイコン一つ 確信度 high

因果連鎖: 御霊図鑑（札絵・よみ・所属・公式紹介文・解禁の仕掛け）を開く導線は盤面下の階梯タップだけ → その標的は実測16〜22pxで半分が押し所の床（両辺24px）を割る（公式トンマナの hit-target は44px）→ しかも <img> に JS のクリックを付けただけなので hover も focus も無く、押せる印もキーボード経路も無い → 作り込みが最も厚い部分に、いちばん細い入口が付いている。

根拠: OBS-B6（標的16×16px・開くことは確認済み・入口は他に無い）。同じ場所を、独立に回した金継ぎが見立て問い7で指している（`SHINDAN-20260828.md` 見立て2件目）。異なる2つの道具が同じ一点で一致した。

Nielsen: #6 記憶より認識 ／ #7 柔軟性と効率。UX層: 骨格（導線）。インパクト: 効果（図鑑・称号という価値に到達しない）。

注記: 金継ぎの検査器は「小タップ標的0件」と報告した。これは <img>＋addEventListener を標的として数えない実装だからで、「無い」ではなく「見ていない」。手計測で見つけた。

R-3 最初の2.87秒、遊べる印が画面に無い 確信度 medium

因果連鎖: オープニングは札絵を全画面で見せる演出で、案内カードは札絵の読み込み完了から2.6秒後に出る（保険5秒）→ 実測で開いてからカードが出るまで2.87秒（Artifact版2.873秒）→ その間、題字も遊び方も入口のボタンも無い → SNSのリンクを踏んだ人が最初に見るのは、操作できるものが何も無い1枚絵。

根拠: OBS-A1（`card_ready_ms` = 2870）、A-1a-open-300ms.png（300ms時点の画面には札絵しか無い）、OBS-D10（2873ms）。実装は game.js:1195 の setTimeout(showCard, reducedMotion ? 400 : 2600)。

Nielsen: #1 可視性。UX層: 骨格。インパクト: 効率＋満足。

制約: 「ここで離脱するか」は測っていない。AI代理は待てるが人は待たない、という一般則を当てはめているだけで、この作品での離脱は観察していない。reduced-motion 設定では400msに短縮される経路があることも申し添える（この設定は未検証）。

R-4 進みの目盛りが、9pxの英字と背景の月にしか無い 確信度 medium

因果連鎖: 進み具合を示すものは3つ——ヘッダーの SCORE / BEST / NEXT（いずれもラベルが9pxの英字大文字）、盤面下の階梯（10個並ぶが現在地の印が無く、到達済みと未到達が同じ見え方）、canvas の背景の月の満ち欠け（気づかなければ存在しない）→ 「自分がどこまで来たか」を読める場所が、小さいか、印が無いか、暗い。

根拠: OBS-B5（ラベル9px・色 #9D93B5・階梯に現在地マーカー無し）。金継ぎの型紙 uppercase-labels×4・english-labels×4 が同じ div.label 群を指した（2つの道具の一致・2件目）。金継ぎ側の修理でこの4件を日本語化すると定番度は42→25に落ちる。

Nielsen: #1 可視性 ／ #2 実世界との一致（日本語のゲームに英字のラベル）。UX層: 表層＋骨格。インパクト: 効率＋満足。

R-5 見せ場を確かめる仕掛けが、見せ場まで届かない 確信度 high（受入NG）

因果連鎖: SPEC §9 は #test を「咲耶×2 → 満月成就、6秒後にもう一組 → 満月×2 → 皆既月蝕」と定めている → 実装（game.js:1286-1296）は咲耶を壺の左右2点へ落とすだけで、2体が接触する保証が無い → 実測では満月が1体できたところで止まり、132秒待っても皆既月蝕は出なかった（咲耶2体が満月をはさんで左右に離れて静止）→ この作品でいちばん重い演出を、作り手が確かめる手段が無い。

根拠: OBS-B7。B-7a-cutin.png（満月成就は2.967秒後に出た）、B-7d-no-eclipse.png（132秒後の盤面・SCORE 55＝満月1体ぶん）。

Nielsen: 該当なし（UIの課題ではなく要件の課題。無理にヒューリスティック番号を付けない）。UX層: 要件。インパクト: 効果（検品可能性そのもの）。

注記: これはプレイヤーが触る機能ではない。だが検品担当（結）を採用した理由——「作った本人が検品していたから不具合が残った」——に直結する。確かめる手段が確かめたいものに届かないなら、その演出は毎回「たぶん動いている」で出荷される。

I. 結論

公開を止める課題は無い。遊びの芯は通っており、配布経路の差もない。2026-08-18の公開判断は妥当だった。

次工程への論点（改善案は分析ではないので分けて置く）:

  1. R-1 は直す価値が高い。「夜が明けた」を終端として定義する（物理と合体を止めるか、結果を凍結せず追従させるか）。どちらを選ぶかは設計の判断で、分析の持ち場ではない
  2. R-2 と R-4 は、金継ぎ側の追補CSSに修理デモが既にある（data/kintsugi/2026-08-28/kintsugi-repair.css）。ただし押し所を44px（公式の hit-target）まで満たすには <button> で包む実装が要る
  3. R-3 と R-5 は、直す前に人間で確かめたほうがよい。2.87秒が本当に長いのか、#test をこれから何回使うのか、で価値が変わる

人間で確かめ直すべき項目（このUTでは測っていない）:

  • 初見の第一印象と離脱——R-3 の2.87秒。AI代理は待つが、人は待たない
  • 実機のスマホ（iOS Safari / Android Chrome）——SPEC §8 のダブルタップズーム抑止・ピンチ抑止は未検証
  • 音の実聴——復号の成功は確認したが、音量バランス・琴の音階・鈴の間隔は聴いていない
  • 「面白いか」——目付は「壊れていないか」「使えるか」を測る道具で、面白さは測らない。それは講評の持ち場であり、最後はオーナーの耳と目
